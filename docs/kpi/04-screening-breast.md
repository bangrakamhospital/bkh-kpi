## 4. ตัวหาร B

คนที่มีคุณสมบัติครบทุกข้อ

1. เพศหญิง (`person.sex = '2'`)
2. อายุ 40–70 ปีเต็ม **ณ 1 ต.ค. ของปีงบฯ** โดย `periodStart − 71 ปี < birthdate ≤ periodStart − 40 ปี`
3. อยู่ในเขตรับผิดชอบ (TYPEAREA 1, 3) ในหมู่บ้านของเขต (ไม่นับหมู่ 0), ยังมีชีวิต และยังไม่จำหน่าย
4. **คัดออก**ผู้ที่มีการวินิจฉัยมะเร็งเต้านม ICD-10 `C50` (รวมรหัสย่อย) ใน `ovstdiag` **ก่อน 1 ต.ค. ของปีงบฯ** (สมมติฐาน ดูข้อ 7)
5. นับเป็นคน (distinct `person_id`)

B = eligible (ตัวคูณ 1)

## 5. ตัวตั้ง A

คนใน B ที่ได้รับ CBE อย่างน้อย 1 ครั้งระหว่าง 1 ต.ค. ถึง `dataAsOf` (นับทุกผลตรวจ) คนละ 1 ครั้งต่อปีงบฯ และนับเข้าเดือนของการตรวจครั้งแรก

## 6. สูตร

```
ร้อยละ = A / B × 100   (ทศนิยม 2 ตำแหน่ง, B = 0 → 0)
```

## 8. SQL สำหรับ HOSxP (verify แล้ว)

> ตรวจกับฐานจริง (`bkhosxp`) ผ่าน skill `db-cli` เมื่อ 2026-11-06 ด้วย DESCRIBE / COUNT / GROUP BY เท่านั้น โค้ดจริงอยู่ที่ `src/lib/kpi/sql/screening-cancer-hosxp.ts`

### 8.1 สิ่งที่พบ

| รายการ | สิ่งที่พบในฐานจริง |
| --- | --- |
| `pp_special`, `pp_special_type`, `ovst` | เหมือน CX (03 ข้อ 9.1) |
| `ovstdiag.icd10` ช่วง `'C50'` ถึง `< 'C51'` | icd10 เก็บแบบไม่มีจุด (เช่น `C509`) ใช้ช่วง string ได้ |
| `person.sex` | `'2'` = หญิง |

รหัส SPECIALPP กลุ่มมะเร็งเต้านม (Z123) ในตาราง `pp_special_type` ของ รพ. นี้:

| รหัส | ความหมาย (ตามชื่อในตาราง) |
| --- | --- |
| `1B0030`–`1B0033` | ตรวจคัดกรอง (โดยเจ้าหน้าที่) ได้ผลปกติ + ประวัติการตรวจด้วยตนเอง (ปกติ / ผิดปกติ / ไม่เคย / ไม่ระบุ) |
| `1B0034`–`1B0037` | ตรวจคัดกรองได้ผลผิดปกติ + ประวัติการตรวจด้วยตนเอง |
| `1B0039` | ตรวจคัดกรองมะเร็งเต้านม ไม่ระบุรายละเอียด |
| `1B003` | รหัสกลุ่มที่ยกเลิกแล้ว (`is_active = 'N'`) ไม่นับ |

- รหัสทั้งกลุ่ม `1B0030`–`1B0039` คือ CBE (ผลของเจ้าหน้าที่ + ประวัติ BSE ของผู้รับบริการ) **ไม่มีรหัส BSE อย่างเดียว** ใน SPECIALPP จึงไม่มีรหัส BSE ปนในรายการ
- เดิมโค้ดนับแค่ `1B0030`, `1B0031` ตอนนี้นับ `1B0030`–`1B0039` (`1B0038` ไม่มีในตาราง คงไว้เผื่ออนาคต) ในทางปฏิบัติแทบทั้งหมดเป็น `1B0030` จึงเปลี่ยนตัวเลขแค่เล็กน้อย

**ข้อควรระวัง (ยังต้องยืนยันกับผู้รับผิดชอบงาน):** HOSxP สร้าง `1B0030` จากบัญชีงานสตรี `person_women_breast_cancer_test` เมื่อเทียบรายการ `1B0030` ปีงบฯ 2569 กับบันทึกในบัญชีนั้น (คนเดียวกัน วันเดียวกัน) ราว 97% มีชนิดการตรวจ (`breast_test_type`) เป็น **"ตรวจด้วยตนเอง"** มีเพียงส่วนน้อยที่เป็น "โดยเจ้าหน้าที่" แปลว่าข้อมูลที่ส่ง HDC เป็นรหัส CBE แต่หน้างานอาจบันทึกเป็น BSE (หรือเลือกชนิดการตรวจผิด) โค้ดยังนับตามรหัส SPECIALPP เพื่อให้ตรงกับ HDC แต่ตัวเลข CBE จริงอาจต่ำกว่านี้มาก

### 8.2 SQL (MySQL/MariaDB)

พารามิเตอร์

- `:periodStart` = `:countFrom` = 1 ต.ค. ของปีงบฯ
- `:dataAsOf` = วันตัดข้อมูล
- `:birthOnOrBefore` = periodStart − 40 ปี
- `:birthAfter` = periodStart − 71 ปี
- `:icdFrom` = `'C50'`, `:icdToExclusive` = `'C51'`

```sql
-- Verified with db-cli, see 8.1
-- target filter (B) on person p:
--       p.house_regist_type_id IN (1, 3)
--   AND p.person_discharge_id = 9
--   AND COALESCE(p.death,'N') <> 'Y'
--   AND p.birthdate IS NOT NULL
--   AND p.village_id IN (SELECT cv.village_id FROM village cv
--                        WHERE TRIM(LEADING '0' FROM TRIM(cv.village_moo)) <> '')
--   AND p.sex = '2'
--   AND p.birthdate <= :birthOnOrBefore
--   AND p.birthdate >  :birthAfter
--   AND NOT EXISTS (SELECT 1 FROM ovstdiag d
--                   WHERE d.hn = p.patient_hn
--                     AND d.icd10 >= :icdFrom AND d.icd10 < :icdToExclusive
--                     AND d.vstdate < :periodStart)

-- screened subquery sc:
SELECT sp.person_id, MIN(o.vstdate) AS first_screen_date
FROM pp_special ps
JOIN pp_special_type pt ON pt.pp_special_type_id = ps.pp_special_type_id
JOIN ovst o            ON o.vn = ps.vn
JOIN person sp         ON sp.patient_hn = o.hn
WHERE pt.pp_special_code IN ('1B0030','1B0031',...,'1B0039')
  AND o.vstdate >= :countFrom
  AND o.vstdate <  DATE_ADD(:dataAsOf, INTERVAL 1 DAY)
GROUP BY sp.person_id;
```

query B, A รายเดือน, รายหมู่ และรายชื่อ สร้างด้วย `buildScreeningSql()` แบบเดียวกับ CX (03 ข้อ 9.2) เนื่องจาก countFrom = periodStart จึงไม่มี bucket `'prior'`
