# คลินิกทันตกรรม (`/clinic/dental`)

> กลุ่มเมนู "ประมาณการรายได้แยกคลินิก" — ผู้รับบริการ หัตถการ ค่าบริการแยกสิทธิ ภาระงาน และตัวชี้วัดคุณภาพของงานทันตกรรม โรงพยาบาลบางระกำ
> ข้อมูลจาก HOSxP เท่านั้น (ไม่ใช้ HDC) ข้อมูลสรุปเท่านั้น ไม่มีข้อมูลระบุตัวผู้ป่วย ปีงบประมาณ 1 ต.ค.–30 ก.ย.
> โค้ด: SQL `src/lib/kpi/sql/dental-clinic-hosxp.ts`, loader `src/lib/kpi/dental-clinic.ts`, types `src/lib/kpi/dental-clinic-types.ts`, UI `src/components/kpi/dental/*`, หน้า `src/app/clinic/dental/page.tsx`
> ตรวจด้วย db-cli 2026-11-18

## 1. ขอบเขต: visit ทันตกรรม

ทันตกรรม **ไม่ได้นับจาก `ovst.main_dep`** เพราะผู้ป่วยราว 1 ใน 6 ลงทะเบียนที่คลินิกอื่น (NCD 062, ANC 022, ER 011 ฯลฯ) แล้วถูกส่งมาทำฟัน หน่วยนับจึงเป็น `dtmain` (หัตถการ 1 แถวต่อรายการ)

- **visit ทันตกรรม** = `vn` ที่มีแถว `dtmain` ของห้องฟัน `depcode` **008** (ห้องตรวจทันตกรรม) หรือ **046** (ห้องฟันออกหน่วย) ที่ `vstdate` อยู่ในปีงบฯ ไม่นับ tmcode `000174` "ไม่รอรับบริการ"
- **ไม่รวม PCU**: visit ที่ลงทะเบียนแผนก PCU (030–041, 057, 066 ตาม `kskdepartment` ที่ชื่อมี "PCU") และหัตถการของห้องฟัน PCU (057 PCU เมืองใหม่-ทันตกรรม, 066 PCU ทันตกรรม) ไม่นับในทุกตัวเลข แสดงเป็นหมายเหตุ "ไม่นับรวม" (FY2569: 3,505 visit, 838,705 บาท)
- **หน่วยบริการ**: `OUTREACH` (ออกหน่วย) เมื่อ `main_dep = 046` หรือ visit ไม่มีแถวของห้อง 008 เลย, นอกนั้น `HOSPITAL` (ในโรงพยาบาล)
- **ที่มา**: `DENTAL` = ลงทะเบียนห้องฟัน (main_dep 008/046), `REFERRED` = ลงทะเบียนคลินิกอื่นของ รพ.
- **ปีงบฯ ที่เปิดให้เลือก: 2569 ขึ้นไป** — `dtmain.depcode` ว่างทั้งหมดก่อน ก.พ. 2568 (FY2568 จะเหลือราว 7.5k จาก ~12.9k visit) จึงแยกห้อง/ตัด PCU ไม่ได้

## 2. ค่าบริการ (บาท)

**บาท = รายการใน `opitemrece` ที่ `dep_code` เป็นห้องฟัน (008/046; รวม 057/066 สำหรับยอด PCU ที่ตัดออก)** ของ visit ทันตกรรม — ไม่ใช้ `vn_stat.income` ทั้งก้อน เพราะ visit ที่ส่งมาจาก NCD มียาและ lab ของ NCD (FY2569 ส่วนนี้ ~6.0 ล้านบาท) ซึ่งจะนับซ้ำกับหน้าคลินิกโรคเรื้อรัง

| ช่อง | income |
|---|---|
| ค่าทันตกรรม | 13 ค่าบริการทางทันตกรรม |
| ฟันเทียม | 02 ค่าอวัยวะเทียม (ฟันเทียม ครอบฟัน) |
| หัตถการ | 11 ค่าทำหัตถการ |
| ยา | 03 / 04 / 17 / 20 |
| รังสี | 08 |
| อื่นๆ | ที่เหลือ (พยาบาล 12, PP 21, ฯลฯ) |

ค่ารายการของแผนกอื่นใน visit ที่ลงทะเบียนห้องฟัน (เช่น ค่าบริการผู้ป่วยนอก) แสดงเป็นหมายเหตุ (`registeredOtherBaht`) ไม่รวมในยอด
บาทเป็น "ค่าที่ HOSxP คิด" ไม่ใช่รายรับจริง (กลุ่มเหมาจ่ายได้เงินรายหัว)

**สิทธิ** ใช้กติกาเดียวกับ `/clinic/ncd` (กติกากลาง `src/lib/kpi/sql/clinic-scheme-hosxp.ts` ใช้ร่วมทุกหน้า /clinic): `ovst.pttype` → `pttype.hipdata_code` + `vn_stat.hospmain = 11252` → กลุ่ม "เต็มจำนวน" (FULL) / "เหมาจ่าย hospmain = รพ." (CAPITATION)

**อุดฟันแท้ : ถอนฟันแท้ (ซี่)**: อุด = ICD-10-TM `23871*` (อุดถาวรฟันแท้; ไม่รวมอุดชั่วคราว 2387211 และ pulp capping 2387210) ÷ ถอน = กลุ่มถอนฟันที่ ICD-10-TM หลักที่ 3 = 8 (ฟันแท้: 2381402, 2382600) ฟันน้ำนม (หลักที่ 3 = 7) แสดงแยก

## 5. ภาระงานและเวลารอคอย

- วันทำการ = วันที่ห้อง 008 มี visit; ทันตบุคลากร = `dtmain.doctor` ที่ไม่ซ้ำ (ทุกคน `doctor.position_id = 2`); visit ต่อบุคลากร-วัน = คู่ (doctor, vn) ไม่ซ้ำ ÷ ผลรวมบุคลากรรายวัน
- ออกหน่วย (046) แสดงจำนวนวันและ visit/วันแยก
- **เวลารอคอย (ค่าประมาณ)**: ลงทะเบียน (`ovst.vstdate + vsttime`) → `MIN(dtmain.begin_time)` ของห้อง 008 เฉพาะ visit ที่ `main_dep = 008` ไม่รวมวันนี้ วัด 0–720 นาที `begin_time` คือเวลาบันทึกหัตถการ (`end_time = begin_time` ครึ่งหนึ่ง) จึงเป็น "ลงทะเบียน → ได้รับบริการแล้ว" ไม่ใช่เวลาเข้าห้อง `ovst_service_time` ไม่มีจุดของห้องฟัน (OPD-DOCTOR มีเพียง ~3% ของ visit ห้องฟัน) จึงไม่ใช้

## 7. ประสิทธิภาพ query

6 query ขนานกัน FY2569: VISITS 2.5 s, COHORT 1.4 s, PROCEDURES 2.0 s, DAYS 2.4 s, WAIT 1.1 s, DM 1.9 s (เวลา db-cli รวม overhead) — `dtmain` อ่านแบบ full scan (~644k แถว ~0.3 s; optimizer เลือกเองแทน `ix_vstdate` ซึ่งเร็วพอกัน) ตารางอื่นเข้าทาง index `vn` / PK; DM query ใช้ derived table ของ dtmain group by hn (EXISTS ต่อคนใช้ 9 s) แคช "use cache" รายปีงบฯ (`hours` ปีที่ยังไม่ปิด, `days` ปีที่ปิดแล้ว) tag `kpi:dental-clinic`

## 8. ที่ไม่ได้ทำ / ข้อจำกัด

- **รายรับจริง / การเบิกจ่าย** (e-claim, ค่าทันตกรรมจ่ายแยกของ สปสช.): ไม่มีในหน้านี้ แสดงเฉพาะค่าที่ HOSxP คิด
- **ค่าใช้จ่ายที่ผู้ป่วยจ่ายเอง**: `vn_stat.paid_money` เป็นของทั้ง visit แยกเฉพาะทันตกรรมไม่ได้ จึงไม่แสดง
- **เกณฑ์ทางการ** ของตัวชี้วัด (เช่น DM ตรวจช่องปาก): ไม่ใส่ เพราะยังยืนยันเกณฑ์ปีปัจจุบันไม่ได้ (`target: null`)
- **เวลาทำหัตถการ (chair time)**: `begin_time/end_time` ของ dtmain ไม่ใช่เวลาจริง
- **ทันตแพทย์ vs ทันตาภิบาล**: `doctor.position_id` = 2 ทุกคน แยกไม่ได้
- **DMFT / สภาวะช่องปาก, ผู้สูงอายุฟันคู่สบ**: ต้องใช้ `dental_care` / แบบสำรวจ ข้อมูลไม่ครบ ไม่ทำ
- `dt_appt` ว่าง ใช้ `oapp` แทน
