# หน้ามาตรฐานรายคลินิก (`/clinic/[clinic]`, กลุ่มเมนู "ประมาณการรายได้แยกคลินิก")

หน้าเดียวใช้ร่วมกับทุกคลินิกชนิด "standard" ในทะเบียนคลินิก แสดงผู้รับบริการ ค่าใช้จ่ายตามสิทธิ หมวดค่าใช้จ่าย รายการค่าบริการ วินิจฉัยหลัก ภาระงาน การมาตามนัด และรายเดือน ตามปีงบประมาณ (1 ต.ค.–30 ก.ย.) จาก HOSxP เท่านั้น (ไม่ใช้ HDC) ข้อมูลสรุปเท่านั้น ไม่มีข้อมูลระบุตัวผู้ป่วย

คลินิกที่มีนิยามเฉพาะ (`/clinic/ncd`, `/clinic/pt`, `/clinic/dental`) เป็นหน้าแยก (static segment ซึ่ง Next.js เลือกก่อน dynamic segment) ตัวชี้วัดเฉพาะของคลินิกอื่น (เช่น ER, ตา, จิตเวช) ทำเป็นหน้าเฉพาะภายหลังได้โดยเปลี่ยน `kind` ในทะเบียนเป็น `"special"` แล้วเพิ่ม route ของตัวเอง

## ไฟล์

| ส่วน | ไฟล์ |
|---|---|
| ทะเบียนคลินิก (pure) | `src/lib/kpi/clinic-registry.ts` (`CLINICS`, `STANDARD_CLINICS`, `findStandardClinic`, `clinicUnits`, `DEPARTMENT_NAMES`) เมนู `ClinicSubNav` อ่านจากที่นี่ |
| สิทธิ (ใช้ร่วมทุก /clinic) | `src/lib/kpi/sql/clinic-scheme-hosxp.ts` (กติกาสิทธิ, CASE, mask เต็มจำนวน/เหมาจ่าย, `SCHEME_NAMES`, `PAY_GROUPS`) + `src/lib/kpi/clinic-scheme-types.ts` |
| SQL | `src/lib/kpi/sql/standard-clinic-hosxp.ts` (`standardClinicSql(clinic)` → visits / cohort / days / items / pdx) |
| loader | `src/lib/kpi/standard-clinic.ts` (`getStandardClinicSummary(slug, fiscalYear)`, cache tag `kpi:standard-clinic` และ `kpi:standard-clinic:<slug>`) |
| types | `src/lib/kpi/standard-clinic-types.ts` (`StandardClinicSummary`) |
| UI | `src/components/kpi/standard/*`, ชิ้นส่วนกลาง `src/components/kpi/clinic/*` (StatCard, StatTile, GroupCard, FiscalYearBar, ClinicPanel, ClinicTable, PayGroupPanel, MonthTable), route `src/app/clinic/[clinic]/page.tsx` |

Route: `generateStaticParams` คืน slug ของคลินิก standard ทุกตัว (Cache Components ไม่มี `dynamicParams`) slug ที่ไม่อยู่ในทะเบียนหรือเป็นหน้าเฉพาะ → `notFound()` หน้าอยู่หลัง login gate ของ `/clinic/*` (proxy + `RequireLogin`) และบันทึก `PageViewAudit` path `/clinic/<slug>`

Cache: `io()` ก่อน, `"use cache"` ต่อ (คลินิก, ปีงบฯ), `cacheLife("hours")` ปีที่ยังไม่สิ้นสุด / `"days"` ปีที่ปิดแล้ว 5 คิวรีรันขนานกัน ถ้าคิวรีใดล้มเหลวหน้าแสดงข้อความผิดพลาด ไม่ cache

## ขอบเขตและสมมติฐาน

- **visit ของคลินิก** = แถว `ovst` ที่ `main_dep` อยู่ใน `depcodes` ของคลินิก และ `vstdate` ในปีงบฯ (รวมวันนี้ เหมือนหน้า NCD) **คน** = `ovst.hn` ไม่ซ้ำ การแยกตามเดือน/สิทธิ/แผนกนับคนซ้ำข้ามกลุ่มได้ ผลรวมของกลุ่มจึงมากกว่าคนทั้งหมด
- **ค่าใช้จ่าย** = `vn_stat` ของ visit (ทุกรายการใน vn เดียวกัน) ไม่ใช่รายรับจริง **รวมค่ากายภาพ/ทันตกรรมที่ทำใน visit นั้นด้วย** ซึ่งหน้าคลินิกกายภาพ/ทันตกรรมนับแยกตามรายการ → **ห้ามรวมยอดข้ามแท็บ** (ข้อความนี้แสดงในหมายเหตุของหน้า)
- หมวดค่าใช้จ่าย: `vn_stat.incNN` = `income_group` NN (ตรวจกับ `opitemrece` แล้ว): ยา inc12 (income 03/04/17/20), lab inc03 (07), รังสี inc04 (08), หัตถการ/วิสัญญี inc06 (11), ทันตกรรม inc11 (13), กายภาพ/เวชกรรมฟื้นฟู inc13 (14), อื่นๆ = ส่วนที่เหลือ (ค่าบริการผู้ป่วยนอก การพยาบาล เวชภัณฑ์มิใช่ยา อุปกรณ์ ฯลฯ)
- **สิทธิ** = กติกาเดียวกับทุกหน้า /clinic (`clinic-scheme-hosxp.ts`): เหมาจ่าย = UC / ประกันสังคม / ต่างด้าวประกันสุขภาพ ที่ `vn_stat.hospmain` = 11252, ที่เหลือ = เต็มจำนวน
- **รายการค่าบริการ** = `opitemrece` ของ visit (`op.vn = o.vn`) ยาทุกรายการ (income 03/04/17/20) รวมเป็นบรรทัดเดียว รายการอื่นเรียงตามจำนวน visit ที่คิดรายการนั้น 15 อันดับ (ชื่อ `nondrugitems.name`, หมวด `income.name`) และยอดของรายการที่เหลือ
- **ICD-10 หลัก** = `vn_stat.pdx` ที่ไม่ว่าง 10 อันดับตาม visit (ชื่อ `icd101.name`) และจำนวน visit ที่ไม่มี pdx
- **ภาระงาน**: วันเปิดบริการ = วันที่มี visit ≥ 1, แพทย์ = `ovst.doctor` ที่ `doctor.position_id = 1`, ผู้ให้บริการ = `ovst.doctor` ทุกตำแหน่ง (เช่น แพทย์แผนไทย พยาบาล ที่ PCU/แผนไทย), visit ต่อแพทย์-วัน = visit ที่แพทย์ตรวจ ÷ ผลรวมแพทย์รายวัน
- **การมาตามนัด** = `oapp` ที่ `depcode` อยู่ใน depcodes ของคลินิก และ `nextdate` ในปีงบฯ; มาตามนัด = `visit_vn` ไม่ว่าง (ER ไม่ค่อยนัด ตัวเลขจึงน้อย)
- **แยกตามแผนก**: คลินิกที่มี `subUnits` แสดงรายหน่วยย่อย และรายแผนกใต้หน่วยย่อยที่มีหลายรหัส คลินิกที่ไม่มี subUnits แต่มีหลายรหัส (OPD, ER) แสดงรายรหัส คลินิกรหัสเดียวไม่แสดงตารางนี้ คนของหน่วยย่อยนับไม่ซ้ำด้วย bitmask แผนกต่อคน (ไม่ใช่ผลรวมของแผนก)
- ปีงบฯ แรกที่เปิดให้เลือก: 2568 (เท่ากับหน้า NCD)

## ประสิทธิภาพ (FY2569, db-cli)

ทุกคิวรีเริ่มจาก `ovst` ช่วง `vstdate` (EXPLAIN: range `ix_vstdate_curdep`, ไม่มีดัชนี `main_dep` จึงกรองหลังอ่านช่วงวันที่) lookup อื่นใช้ primary key / `ix_vn` (`opitemrece`) แต่ละคิวรี 1.5–3.7 วินาที รันขนาน 5 คิวรีต่อหน้า (OPD ช้าสุด: visits 2.4 / cohort 2.6 / days 2.3 / items 3.7 / pdx 2.5 วินาที)

| คิวรี | ผล |
|---|---|
| visits | แถวต่อ (เดือน, main_dep, สิทธิ): visit และ vn_stat ทุกหมวด + visit ที่ไม่มี pdx |
| cohort | 1 แถว: คนไม่ซ้ำ ต่อเดือน (m0..m11) ต่อสิทธิ (s0..s9, pay_full, pay_capitation) ต่อแผนก (d<i>) ต่อหน่วยย่อย (u<i>) ด้วย `BIT_OR(1 << index)` ต่อคน |
| days | ต่อวัน: visit, แพทย์, visit ที่แพทย์ตรวจ, ผู้ให้บริการ (ทั้งปีจาก `WITH ROLLUP`) + นัดต่อวันนัด |
| items | ยารวม 1 แถว + รายการอื่น 15 อันดับตาม visit (`ROW_NUMBER`) + ยอดรวมรายการอื่นทั้งหมด (window `SUM`) |
| pdx | 10 อันดับ `vn_stat.pdx` |
