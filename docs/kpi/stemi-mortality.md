## 1. นิยามทางการ (KPI Template 2569 หน้า 67–68)

| หัวข้อ | เนื้อหาในเอกสาร |
| --- | --- |
| STEMI | กล้ามเนื้อหัวใจขาดเลือดจนเกิดการตายของกล้ามเนื้อ และคลื่นไฟฟ้าหัวใจผิดปกติชนิด ST-elevation |
| ผู้ป่วย STEMI | ผู้ป่วย STEMI ที่เป็น**ผู้ป่วยใน** หรือ**ผู้ป่วยที่มาตรวจที่แผนกฉุกเฉินและส่งต่อ**ไปยัง รพ. ที่มีศักยภาพสูงกว่า "**โดยนับการเจ็บป่วยในครั้งนั้นเป็น 1 visit**" (หน้า 67) |
| การตายของผู้ป่วย STEMI | การตายจากสาเหตุโรคกล้ามเนื้อหัวใจตายเฉียบพลันชนิด STEMI |
| รหัส | ICD-10 WHO **I21.0–I21.3** (ไม่รวม I21.4 NSTEMI, I21.9, I22) |
| A | จำนวนผู้ป่วยใน รหัส I21.0–I21.3 ที่**เสียชีวิตในโรงพยาบาล**ทั้งหมด |
| B | จำนวนผู้ป่วยใน รหัส I21.0–I21.3 ที่รับไว้รักษาในโรงพยาบาลทั้งหมด |
| สูตร | **(A / B) × 100** — ยิ่งต่ำยิ่งดี |
| เป้าหมาย | ปีงบ 69: **น้อยกว่าร้อยละ 9**; ปีงบ 70: **น้อยกว่าร้อยละ 9** |
| ระยะเวลาประเมิน | รายไตรมาส (รอบ 3/6/9/12 เดือน — เกณฑ์รายรอบเป็น small success เชิงระบบ เช่น CPG, fast track, fibrinolysis, reperfusion rate ≥ 70% ไม่ใช่ค่าอัตราตาย) |
| แหล่งข้อมูล | Thai ACS Registry หรือ HDC |
| Baseline ประเทศ | 2566: 9.46, 2567: 9.01, 2568: 8.06 (Thai ACS Registry) |

ไม่มีข้อกำหนดเรื่อง "ตายภายใน 30 วัน" — A คือ**ตายในโรงพยาบาล** ไม่มีการจำกัดเขตรับผิดชอบ/อายุ/สัญชาติ (ระดับโรงพยาบาล) และไม่พบ script ของ HDC สำหรับตัวชี้วัดนี้ในเอกสารที่มี (ไม่ได้ตรวจกับหน้า HDC จริง) ส่วนที่เหลือจึงเป็นการตีความ (ข้อ 3)

**ข้อสังเกตสำคัญ:** นิยามข้อ 1 ให้นับผู้ป่วย ER ที่ส่งต่อเป็นผู้ป่วยของ รพ. ต้นทาง แต่ A นับเฉพาะตายใน รพ. ดังนั้นสำหรับ รพ.ชุมชนที่ส่งต่อแทบทุกราย ผู้ที่เสียชีวิตที่ รพ. ปลายทางจะ**ไม่อยู่ใน A** ของเรา (และไม่อยู่ใน HOSxP) ค่าที่ได้จึงสะท้อน "ตายก่อน/ระหว่างอยู่ที่ รพ. นี้" เท่านั้น

## 2. การจับคู่กับ HOSxP (verify แล้วผ่าน db-cli)

| องค์ประกอบ | HOSxP |
| --- | --- |
| รหัสโรค | `ovstdiag.icd10` / `iptdiag.icd10` เก็บแบบไม่มีจุด: `I210`, `I211`, `I212`, `I213` ทุก diagtype |
| encounter STEMI (OPD/ER) | visit ใน `ovstdiag` ที่มีรหัสข้างต้น **และ**เป็นการมาแบบเฉียบพลัน: มี `er_regist.vn` หรือ ส่งต่อจาก visit นั้น (`referout.vn`) หรือ admit จาก visit นั้น (`ovst.an`) |
| encounter STEMI (IPD) | `ipt` (ตามวันที่ `regdate`) ที่มีรหัสใน `iptdiag` (พบเฉพาะ I21.3 diagtype 3 ปีละ 1–2 ราย และ refer ทั้งหมด) |
| visit OPD ธรรมดาที่ลง I21.x | **ไม่นับ** — เป็นการ follow-up ของ MI เก่า (ปีงบ 69: 40 visit/10 คน ทั้งหมดไม่ใช่ ER/refer/admit) ควรลงเป็น I25.2 |
| ตายที่ ER/OPD | `ovst.ovstost = '52'` (ตาราง `ovstost`: `death_status = 'Y'` มีค่าเดียว, export code 43 แฟ้ม = 4) |
| ตายใน IPD | `ipt.dchtype IN ('08','09')` หรือ `ipt.dchstts IN ('08','09')` (รหัสมาตรฐาน; ชื่อในตาราง lookup ถูก mask ใน db-cli จึงยืนยันจากความสอดคล้อง: ปีงบ 67–70 มี 529 admission ที่ dchtype 08/09 ทุกรายมี dchstts 08/09 ด้วย และ 503 ราย (95%) ตรงกับ `patient.deathday` ±1 วัน) |
| ส่งต่อ | `referout.vn` = vn ของ OPD/ER (บาง record เก็บ an) และ `ipt.dchtype = '04'` ; `ovst.ovstost = '54'` และ `er_regist.er_dch_type` บันทึกไม่ครบ (er_dch_type ว่างทั้งหมดตั้งแต่ปีงบ 69) จึงไม่ใช้ |
| `patient.deathday` | มีการตายนอก รพ. บางส่วน (ปีงบ 69: 312 คน, ตายใน IPD 168, ER 6) แต่ไม่ครอบคลุมการตายที่ รพ. ปลายทางทั้งหมด ใช้เป็นข้อมูลเสริมเท่านั้น |
| Thrombolytic | `er_regist.do_stemi_balloon`, `stemi_balloon_datetime`, `door_to_needle_second` มีอยู่ แต่ไม่จำเป็นต่อสูตรนี้ (ไม่ได้ตรวจความครบถ้วน) |
| หมู่บ้าน | `person.patient_hn` (1:1) ถ้า `house_regist_type_id IN (1,3)` และอยู่หมู่บ้านจริงของเขต → village นั้น ไม่งั้น village_id 0 (นอกเขต/ไม่ระบุ) **ไม่ตรวจ "ยังมีชีวิต"** เพราะผู้ที่ตายจะถูก mark ตายใน `person` ด้วย ถ้าใช้เงื่อนไขเดียวกับ CKD5 ผู้ตายทุกรายจะตกไปอยู่ village 0 |

## 3. สมมติฐานที่เลือก (ควรยืนยันกับผู้ใช้/ผู้รับผิดชอบงาน NCD-หัวใจ)

1. **หน่วยนับ = episode (การเจ็บป่วยครั้งนั้น)** ไม่ใช่คนและไม่ใช่ visit ดิบ ตามคำว่า "นับการเจ็บป่วยในครั้งนั้นเป็น 1 visit" encounter ของ hn เดียวกันที่ห่างจาก encounter ก่อนหน้าไม่เกิน **28 วัน** (ช่วง acute MI ของ ICD-10, I21 vs I22) ถือเป็น episode เดียว (ปีงบ 68 มี 1 คนที่มี 2 episode ห่างกัน > 28 วัน → B = 25 จาก 24 คน)
2. **B** = episode ที่มี STEMI จาก ER/ส่งต่อ/admit หรือ IPD **รวมผู้ที่ส่งต่อ** (ตามนิยามข้อ 1) และรวม ER visit ที่ไม่ได้ส่งต่อ/admit (ตายที่ ER หรือกลับบ้าน ~1 ราย/ปี) เพราะถ้าตัดออก ผู้ที่ตายที่ ER จะหายจากทั้ง A และ B
3. **ใช้ทุก diagtype** (ไม่ใช่เฉพาะ principal) — ER ที่ pdx เป็นภาวะอื่น (เช่น หัวใจหยุดเต้น) แต่มี STEMI เป็น dx รอง ยังเป็นผู้ป่วย STEMI
4. **A** = episode ที่**ตายที่ รพ. นี้** (ER/OPD `ovstost` 52 หรือ IPD discharge dead) ภายใน **28 วัน**นับจากวันเริ่ม episode (ไม่บังคับว่า visit ที่ตายต้องลงรหัส I21) ไม่ได้ตรวจสาเหตุการตาย (template ระบุ "ตายจากสาเหตุ STEMI" แต่ HOSxP ไม่มีข้อมูลสาเหตุที่เชื่อถือได้สำหรับทุกราย)
5. **ปีงบ** ตามวันเริ่ม episode (`event_date` = วันที่ ER/admit ครั้งแรก) ไม่ใช่วันจำหน่าย ช่วงตายไม่ตัดที่ `dataAsOf` → ปีงบที่จบแล้วนิ่งหลังสิ้นปี 28 วัน
6. ไม่จำกัดอายุ/สัญชาติ/เขต (ระดับโรงพยาบาล) — ปีงบ 69 มี 1 episode อายุน้อยผิดปกติ (< 20 ปี) ควรตรวจ coding

## 5. Performance (EXPLAIN บนฐานจริง)

- `ev` ฝั่ง OPD: range บน index `ovstdiag.icd10` (รหัส 4 ตัว + ช่วงวันที่) → `ovst` eq_ref ผ่าน vn; `er_regist` PK, `referout.ix_vn` เป็น subquery ราย row
- `ev` ฝั่ง IPD: `ipt` full scan (~111k แถว, เหมือน CKD5) join `iptdiag` ผ่าน `an` — ไม่มี index บน `iptdiag.icd10`
- ความตาย: correlated subquery ราย episode (≤ ~30 แถว) ผ่าน `ovst(hn, vstdate)`, `ipt.hn`, `patient.hn_unique`
- ทุก query 0.03–0.25 s (totals 0.04–0.21 s, monthly/village/eligible ~0.16 s, persons ~0.1–0.2 s)

## 6. Query ใน `STEMI_SQL`

`STEMI_SQL` เป็น `ScreeningSqlSet` (ใช้กับ registry เดิมได้) + `totals`

| query | ผลลัพธ์ |
| --- | --- |
| `totals` | 1 แถว `patients` (B), `deaths` (A), `deaths_any_30d` (ข้อมูลเสริม ไม่ใช่สูตรทางการ) |
| `eligible` | 1 แถว `eligible` = B |
| `monthly` | `bucket` 'YYYY-MM' (เดือนของ event_date), `screened` = A ของเดือน, `eligible` = B ของเดือน (ไม่มี bucket 'prior') |
| `village` | `village_id` (0 = นอกเขต/ไม่ระบุ), `village_moo`, `village_name`, `eligible` (B), `numerator` (A) |
| `personsByVillage` / `personsAll` | 1 แถวต่อ episode: `person_id`, `village_id`, `hn`, `full_name`, `sort_name`, `sex`, `age`, `screen_date` (= วันที่ตาย, NULL = รอด), `event_date`, `status` ('died'/'survived') — ไม่มีค่าทางคลินิก |

พารามิเตอร์: `:periodStart`, `:dataAsOf` (จาก `buildParams(ScreeningSqlContext)`; ไม่ใช้ `countFrom`) และ `:villageId`
