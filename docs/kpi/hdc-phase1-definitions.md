## 2.1 (6.1) ยืนยันวินิจฉัยกลุ่มสงสัยป่วยเบาหวาน

- **ประชากรในเขต**: typearea 1, 3; PERSON.DISCHARGE = 9; PERSON.NATION = 099 (ไทย); อายุ ≥ 35 ปี
- **คัดออก**: ได้รับการวินิจฉัย/ขึ้นทะเบียนเบาหวานมาก่อน (DIAGNOSIS_OPD, DIAGNOSIS_IPD, CHRONIC รหัส E10–E14)
- **B (กลุ่มสงสัยป่วย)**: ประชากรข้างต้นที่ได้รับการคัดกรองเบาหวานในปีงบ และ NCDSCREEN.BSTEST ∈ {1 (FPG หลอดเลือดดำหลังอดอาหาร), 3 (FCBG ปลายนิ้วหลังอดอาหาร)} และ **BSLEVEL ≥ 126 mg/dl**
  - (วิธีที่ 2 ในนิยาม: RCBG/RPG ≥ 110 แล้วคัดกรองซ้ำแบบอดอาหาร ≥ 126 — ผลสุดท้ายยังจบที่ BSTEST 1/3 ≥ 126)
  - นับสะสมคัดกรองตั้งแต่ 1 ต.ค. ถึง **30 มิ.ย.** ของปีงบ (เพื่อให้มีเวลาติดตามก่อนสิ้นปีงบ)
- **A**: คนใน B ที่ได้รับการตรวจยืนยัน **FPG ทางห้องปฏิบัติการ** ในสถานบริการ ตั้งแต่ **วันถัดจากวันคัดกรอง** ภายในปีงบ (1–180 วันก่อนสิ้นปีงบ) — HDC ประมวลจากแฟ้ม **LABFU.LABTEST = 0531002** (glucose ในซีรั่ม/พลาสมา)
- เกณฑ์รายรอบ: 6 เดือน ≥ 50, 9 เดือน ≥ 60, 12 เดือน ≥ 70

## 2.2 (6.2) ยืนยันวินิจฉัยกลุ่มสงสัยป่วยความดันโลหิตสูง

- **ประชากรในเขต / อายุ**: เหมือน 2.1
- **คัดออก**: ได้รับการวินิจฉัย/ขึ้นทะเบียนความดันโลหิตสูงมาก่อน (I10–I15)
- **B (กลุ่มสงสัยป่วย)**: ได้รับการคัดกรองความดันในปีงบ และค่าเฉลี่ย **SBP 140–179** และ/หรือ **DBP 90–109** mmHg; คัดกรองสะสม 1 ต.ค. – 30 มิ.ย.
- **A**: คนใน B ที่ได้รับการยืนยันโดย
  - **HBPM** วัดความดันที่บ้านติดต่อกัน ≥ 7 วัน (บันทึกในระบบ HDC จังหวัด — **ไม่อยู่ใน HOSxP**) หรือ
  - **OBPM** วัดความดันซ้ำในสถานบริการเดิม (SERVICE.SBP / SERVICE.DBP) ภายใน 1–90 วันก่อนสิ้นปีงบ หลังวันคัดกรอง
  - ถ้ามีทั้งสองวิธี ใช้ HBPM เป็นหลัก
- เกณฑ์รายรอบ: 6 เดือน ≥ 60, 9 เดือน ≥ 70, 12 เดือน ≥ 80
- ⚠️ ระดับโรงพยาบาลจาก HOSxP นับได้เฉพาะ **OBPM** — ผลอาจต่ำกว่า HDC ที่รวม HBPM ต้องแสดงหมายเหตุนี้บนหน้าเว็บ

### 2.x ประสิทธิภาพและรูปแบบ SQL (2.1 และ 2.2)

- ทุก query มีรูป `WITH su AS (กลุ่มสงสัยรายคน), tg AS (B + confirm_date) SELECT ... FROM tg` และอ้าง `tg` ครั้งเดียว
- `confirm_date` เป็น correlated scalar subquery (ใช้ index `lab_head(hn, order_date)` / `opdscreen(hn)`) ประเมินเฉพาะคนใน B
- `su STRAIGHT_JOIN person` บังคับอ่านกลุ่มสงสัยก่อน: ถ้าใช้ JOIN ปกติหรือแยก `cf` เป็น derived table ที่มี GROUP BY, MariaDB เลือกแผน "split materialized / LATERAL DERIVED" ที่สรุป screening head ใหม่ทีละคน ทำให้ query รายหมู่/รายชื่อรายหมู่เกิน 60 วินาที
- หลังแก้: EXPLAIN = scan `person_dmht_risk_screen_head` ครั้งเดียว (~160k แถว), `person` ด้วย PK, ที่เหลือใช้ index; เวลา 0.1–3 วินาทีต่อ query (ครั้งแรกที่ buffer ยังเย็น ~3 วินาที)
- รายชื่อ: คอลัมน์เดียวกับ query รายชื่อของ KPI 1 (`person_id, village_id, hn, full_name, sort_name, sex, age`) โดย `screen_date` = **วันที่ยืนยัน** (NULL = ยังไม่ยืนยัน) และเพิ่ม `suspect_date` = วันคัดกรองที่เข้าเกณฑ์ ไม่ส่งค่าน้ำตาล/ความดันออกจากฐานข้อมูล

## 11.3–11.5 (30.3, 30.5, 30.6) RLU ผู้ป่วยเบาหวานได้รับการตรวจ lab อย่างน้อยปีละ 1 ครั้ง

- **กลุ่มผู้ป่วยโรคเบาหวาน**: ประชากรที่ได้รับการวินิจฉัยว่าเป็นโรคเบาหวาน (B = "จำนวนผู้ป่วยที่ได้รับการวินิจฉัยว่าเป็นโรคเบาหวานทั้งหมด")
- **A**: ผู้ป่วยในกลุ่มนั้นที่ได้รับการตรวจ HbA1c / LDL / Creatinine อย่างน้อย 1 ครั้งในปีงบประมาณ
- หลักการ RLU: ตรวจ HbA1c, LDL, Creatinine อย่างน้อยปีละครั้ง > 70% (ปี 70 > 80%) และไม่ตรวจซ้ำภายใน 90 วันเกิน 5% (ปี 70 ≤ 4%)
- ตัวชี้วัด RLU เป็นตัวชี้วัด **ระดับโรงพยาบาล** ไม่จำกัด typearea

### คำถามที่ยังต้องให้ผู้ใช้ยืนยัน
