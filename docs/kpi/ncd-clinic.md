# คลินิกโรคเรื้อรัง (`/clinic/ncd`, กลุ่มเมนู "ประมาณการรายได้แยกคลินิก")

แท็บ "NCD Clinic" รายงานคลินิกโรคไม่ติดต่อเรื้อรังของโรงพยาบาล (เบาหวาน ความดันโลหิตสูง ไขมันผิดปกติ หอบหืด/COPD) ทั้ง **คุณภาพตัวชี้วัด** และ **ค่าใช้จ่าย/รายได้ตามสิทธิ** ตามปีงบประมาณ (1 ต.ค.–30 ก.ย.) จาก HOSxP เท่านั้น (ไม่ใช้ HDC) ข้อมูลสรุปเท่านั้น ไม่มีข้อมูลระบุตัวผู้ป่วย แรงบันดาลใจจาก infographic รายงาน NCD clinic ของโรงพยาบาลอื่น

Cache: `io()` ก่อน, `"use cache"` ต่อปีงบฯ, `cacheLife("hours")` ปีที่ยังไม่สิ้นสุด / `"days"` ปีที่ปิดแล้ว 4 คิวรีรันขนานกัน (FY2569: 3.0 / 5.2 / 2.3 / 2.7 วินาที) ถ้าคิวรีใดล้มเหลวหน้าแสดงข้อความผิดพลาด ไม่ cache MariaDB ประเมิน CTE ใหม่ทุกครั้งที่ถูกอ้างอิง (คิวรีแบบ UNION หลาย CTE ใช้ 38 วินาที) จึงออกแบบให้แต่ละคิวรีอ่าน visit ของคลินิกครั้งเดียว: จำนวนคนต่อเดือน/สิทธิใช้ bitmask ต่อคน (`BIT_OR(1 << index)`) ในคิวรีเดียวกับตัวชี้วัดคุณภาพ, ทั้งปีของแพทย์ใช้ `WITH ROLLUP`, เวลารอคอยใช้ `CROSS JOIN` กับรายการ measure

## ขอบเขตและสมมติฐาน

- **คลินิก NCD** = `ovst.main_dep` ใน `062` "จุดซักประวัติโรคไม่ติดต่อเรื้อรัง" (จุดลงทะเบียน/ซักประวัติของคลินิก ทุก visit ของคลินิกเริ่มที่นี่) และ `047` "ห้องตรวจโรค NCD" (ห้องแพทย์ของคลินิก มีเป็น main_dep เพียง 6 visit) ไม่รวมคลินิกของ PCU (`031`/`032`/`037`/`038`) ซึ่งเป็นหน่วยบริการอื่น คลินิกเปิดวันทำการ (FY2569: 241 วัน จันทร์–ศุกร์)
- **visit** = แถว `ovst` ของคลินิกในปีงบฯ (`vstdate`) **คน** = `ovst.hn` ไม่ซ้ำ (cohort ของปี) การแยกตามเดือน/สิทธิ/กลุ่มโรคนับคนซ้ำได้ข้ามกลุ่ม (คนหนึ่งมีได้หลายเดือน หลายสิทธิ หลายโรค) ผลรวมของกลุ่มจึงมากกว่าจำนวนคนทั้งหมด
- **กลุ่มโรค** = ICD-10 ใน `ovstdiag` (ทุก diagtype) ของ visit คลินิกในปีงบฯ: DM E10–E14, HT I10–I15, DLP E78, หอบหืด/COPD J44–J46, อื่นๆ = ไม่มีรหัส 4 กลุ่มนี้เลย (เช่น CKD, ไทรอยด์) DM/HT ของตัวชี้วัดคุณภาพใช้นิยามเดียวกัน (ไม่ใช้ทะเบียน `clinicmember` เพราะทะเบียน 001/002 รวมผู้ป่วยของ PCU และไม่มีประวัติสถานะย้อนหลัง)
- **lab ของคน** นับทั้งปีงบฯ ทุก visit (`lab_head.hn` + `order_date` แบบ RLU) เพราะ HbA1c ส่วนหนึ่งสั่งที่ visit ห้อง lab ไม่ใช่ visit คลินิก ผลต้องไม่ว่าง; HbA1c / LDL ต้องเป็นตัวเลข
- ปีงบฯ ที่ยังไม่สิ้นสุดนับถึงวันที่มีข้อมูล (ตัวหารเป็นคนที่มาแล้วในปีนั้น)

## นิยามตัวชี้วัด

### คุณภาพ (`indicators`)

ตัวหาร DM = คน DM ของคลินิก (ไม่ได้ตรวจ = ไม่ผ่าน), HT = คน HT ของคลินิก

| code | ตัวชี้วัด | ตัวตั้ง | ตัวหาร | เกณฑ์ (แหล่ง) |
|---|---|---|---|---|
| `DM_HBA1C_CONTROL` | DM ควบคุมน้ำตาลได้ดี | HbA1c **ครั้งล่าสุด** ในปี < 7 | DM | ≥ 40% (HDC / Service Plan NCD) |
| `DM_HBA1C_TESTED` | DM ตรวจ HbA1c ≥ 1 ครั้ง/ปี | มีผล HbA1c ในปี | DM | > 70% ปี 69, > 80% ปี 70+ (KPI Template 30.3) |
| `DM_HBA1C_REPEAT_90D` | HbA1c ซ้ำภายใน 90 วัน (ยิ่งน้อยยิ่งดี) | **ครั้ง** HbA1c ที่ห่างจากครั้งก่อนของคนเดียวกัน < 90 วัน | ครั้ง HbA1c ทั้งหมดของ DM (วันสั่งไม่ซ้ำต่อคน) | ≤ 5% ปี 69, ≤ 4% ปี 70+ (30.2) |
| `DM_LDL_TESTED` | DM ตรวจ LDL ≥ 1 ครั้ง/ปี | มีผล LDL ในปี | DM | > 70% / > 80% (30.5) |
| `DM_LDL_CONTROL` | DM LDL ล่าสุด < 100 | LDL ล่าสุด < 100 mg/dL | DM | ไม่มีเกณฑ์ทางการ (`target: null`) แสดงเพื่อติดตาม |
| `DM_CR_TESTED` | DM ตรวจ Creatinine ≥ 1 ครั้ง/ปี | มีผล Cr ในปี | DM | > 70% / > 80% (30.6) |
| `DM_EYE_SCREEN` | DM ตรวจจอประสาทตา | `do_eye_screen = 'Y'` ในปี | DM | ≥ 60% (HDC) |
| `DM_FOOT_SCREEN` | DM ตรวจเท้า | `do_foot_screen = 'Y'` ในปี | DM | ≥ 60% (HDC) |
| `HT_BP_CONTROL` | HT ควบคุมความดันได้ดี | BP **ครั้งล่าสุด** ที่คลินิก < 140/90 | HT | ≥ 60% (HDC) |
| `DMHT_CKD_SCREEN` | DM/HT คัดกรองโรคไต | มี eGFR **และ** urine microalbumin/UACR ในปี | DM หรือ HT | ≥ 80% (Service Plan CKD) |

`pass` = เทียบ `percent` (ทศนิยม 1 ตำแหน่ง) กับเกณฑ์ตาม `targetOperator`; `null` เมื่อไม่มีเกณฑ์หรือไม่มีข้อมูล HT ใช้ BP ครั้งเดียว (HDC ใช้ 2 ครั้งล่าสุด) จึงอาจสูงกว่า HDC เล็กน้อย

### อื่นๆ

| field | นิยาม |
|---|---|
| `dmLabPanel` | DM ที่มีผลในปีของแต่ละ lab (HbA1c, LDL, Chol, Cr, K, FBS, UACR) และ `PANEL` = ครบ 5 รายการ HbA1c+LDL+Cr+K+FBS (แนวคิด "บันทึก lab NCD ให้ครบเพื่อเบิก") |
| `hba1cUse` | `personsOverLimit` = DM ที่ตรวจ HbA1c > 2 ครั้ง/ปี (สปสช. จ่าย ≤ 2), `excessTests` = Σ(ครั้ง − 2), `excessBaht` = excessTests × 230 (ประมาณการ เบิกไม่ได้) นับทุกสิทธิ |
| `glucoseTests` | visit คลินิกที่มี FBS lab (76/817) vs DTX (306) ใน lab ของ vn นั้น (แนวคิด FBS → DTX ลดต้นทุน) ไม่มีข้อมูลต้นทุนน้ำยา ค่าบริการทั้งสองแบบ 40 บาทเท่ากัน จึงแสดงเฉพาะจำนวน |
| `waiting` | แยก visit มี lab (มี `lab_head` ใน vn) / ไม่มี lab: `toDoctor` = `vsttime` → `service2`, `toPharmacy` = `vsttime` → `service7`, `screenToDoctor` = `service1` → `service2` มัธยฐาน / P90 จาก histogram ช่องละ 10 นาที (linear ในช่อง) ค่าเฉลี่ยจากจุดกึ่งกลางช่อง ตัด visit ที่ไม่มีเวลา, ติดลบ หรือ > 720 นาที (`measured` < `visits`) และไม่นับ visit ของวันนี้ (`vstdate < CURDATE()`: คนที่ยังรออยู่ยังไม่มี `service2`/`service7` จะเหลือแต่คนที่เสร็จเร็ว) `service_time` เก็บแค่เวลา งานที่ข้ามวันจึงติดลบและถูกตัด "พบแพทย์" = แพทย์ตรวจเสร็จ (ไม่ใช่เวลาเข้าห้อง; ต่างกันมัธยฐาน ~1.5 นาที) |
| `workload` | `clinicDays` = วันที่มี visit, เฉลี่ย/สูงสุด visit ต่อวัน, `daysOverTarget` = วันที่ visit > 120 (แนวคิด "นัดไม่เกิน 100–120 ราย/วัน"), นัด (`oapp.nextdate`) เฉลี่ย/สูงสุด/วันที่เกิน 120, มาตามนัด %, `physicians` = แพทย์ไม่ซ้ำทั้งปี, `avgPhysiciansPerDay`, `visitsPerPhysicianDay` = visit ที่แพทย์ตรวจ ÷ แพทย์-วัน, `days` = รายวัน (วันที่, visit, นัด, แพทย์) |
| `months` | 12 เดือน ต.ค.–ก.ย.: คน, visit, บาทแยกหมวด, visit/บาทกลุ่มเต็มจำนวน vs เหมาจ่าย, วันคลินิก, visit/วัน เฉลี่ยและสูงสุด |
