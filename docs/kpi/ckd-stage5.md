## 3. สมมติฐานที่เลือก (ควรยืนยันกับผู้ใช้/ผู้รับผิดชอบงานไต)

1. **นับคน** ไม่ใช่นับครั้ง แต่ละ hn เป็นรายใหม่ได้ครั้งเดียวตลอดประวัติ (ย้อนดูผล eGFR ทั้งหมดตั้งแต่ 2017)
2. **เหตุการณ์ stage 5** = ผล eGFR < 15 (OPD, ไม่ใช่ AKI, ไม่เคยทำ dialysis) ที่ "ยืนยันความเรื้อรัง" ได้แบบใดแบบหนึ่ง
   - (a) มีผล eGFR **15 ≤ eGFR < 21** อย่างน้อย 90 วันก่อนหน้า (= ข้อ 1 ของนิยาม แต่ขยาย 16–20 เป็น 15–<21 เพื่อไม่ให้ค่าทศนิยม 15.x / 20.x ตกหล่น)
   - (f) มีผล eGFR **< 15** อีกครั้งในช่วง 90–365 วันก่อนหน้า (ผลนี้คือการยืนยันซ้ำ ≥ 3 เดือน) ครอบคลุมข้อ 2 และข้อ 3 ของนิยาม **โดยไม่ตรวจค่าพื้นฐาน 21–60 / "ไม่มีผลเดิม"** (ทำให้กรณีมีผลเดิม > 60 ก็นับได้เมื่อยืนยันซ้ำ) กำหนดเพดาน 365 วันเพื่อไม่ให้ค่าต่ำครั้งเดียวเมื่อหลายปีก่อน (เช่น AKI เก่า) มายืนยันค่าปัจจุบัน
3. **วันที่เป็นรายใหม่ (case_date)** = วันที่เข้าเงื่อนไขครั้งแรก (แบบ a = วันที่ eGFR < 15; แบบ f = วันที่ผลยืนยันซ้ำ) แล้วนับเข้าปีงบที่มีวันนั้น
   - ข้อดี: ผลของปีงบที่จบแล้วไม่เปลี่ยนภายหลัง (ไม่ต้องรอผลยืนยันหลังสิ้นปี) และ B คำนวณจากข้อมูลปัจจุบันได้ตรงกับตอนสิ้นปีก่อน (ตรวจแล้ว: FY68 คำนวณด้วยข้อมูลถึง 30 ก.ย. 68 = 48 เท่ากับคำนวณด้วยข้อมูลถึงวันนี้)
   - ทางเลือก: นับตามวันที่ eGFR < 15 ครั้งแรก (index date) — ปีงบปัจจุบันจะยังไม่นิ่งจนถึง ~3 เดือนหลังสิ้นปี
4. **AKI**: ตัดเฉพาะผล eGFR < 15 ที่มี N17* ใน 90 วันก่อนถึงวันนั้น (ผลอื่นของคนเดิมยังนับได้)
5. **ไม่อยู่ระหว่างนอน รพ.**: ใช้กับผล eGFR ทุกค่าที่นำมาพิจารณา (ทั้งค่าที่ < 15 และค่าก่อนหน้า)
6. **ไม่คัดคนตาย** (นับเหตุการณ์ของปีนั้น) ไม่จำกัดอายุ/สัญชาติ/เขต
7. **ช่วงเปรียบเทียบระหว่างปี**: สูตรทางการใช้ B ทั้งปีก่อน ระหว่างปี A สะสมยังน้อย ร้อยละจะสูงเกินจริง จึงคืนค่า `previous_same_period` (ปีก่อนถึงวันเดียวกัน) ไว้ให้ UI แสดงเทียบด้วย

## 5. Performance (EXPLAIN บนฐานจริง)

- `cand`: ผู้ป่วยที่มี eGFR < 15 ใน [1 ต.ค. ปีก่อน, dataAsOf] (~480 คนใน 2 ปี) MariaDB เลือกสแกน index `ix_hn_order_date` ของ `lab_head` (~1.46M แถว, covering) + `lab_order` PK ~1.5 s
- `eg`: ประวัติ eGFR ทั้งหมดของ cand ผ่าน `lab_head(hn, order_date)` (~9.5k ผล) `STRAIGHT_JOIN` บังคับให้ cand เป็นตัวขับ (ถ้าไม่บังคับ MariaDB full scan `lab_head` และช้ากว่ามาก)
- กฎ (a)/(f) ใช้ window function `COUNT() OVER (PARTITION BY hn ORDER BY TO_DAYS(d) RANGE ...)` อ่าน eg รอบเดียว — เวอร์ชันแรกที่ใช้ self-join `EXISTS` บน CTE เดียวกันหลายครั้งเกิน 60 s
- AKI/RRT เป็นรายการเล็ก (`ovstdiag` ผ่าน index `icd10`, `ipt` full scan ~111k แถว join `iptdiag`) materialise ครั้งเดียว
- ทุก query 2–4 s (totals 2.7–3.5 s, monthly ~2 s, village ~3.2 s, persons ~3–3.7 s) แต่ละ query คำนวณ CTE ใหม่ทั้งหมด จึงควรรันพร้อมกันและ cache ผล
